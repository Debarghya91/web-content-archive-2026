Routing Decision Tree: What Went Wrong, and What to Do Next

A payment came back rejected or returned. Pick the reason code on the notice and work the tree. Each code tells you what it means in plain language, the most likely root cause, the next check to run, the fix in order, what to check first, and who owns the fix.

How to use

  1. Read the reason code on the pacs.002 rejection, the return notice, or the SWIFT NAK.
  2. Click that code below. Do not guess from the amount or the customer name alone.
  3. Run the "What to check first" step before you contact anyone. Most routing errors are fixed by one field check, not by re-sending the payment.
  4. Use the reset button to go back to the code list for the next case.

Golden rule: never re-send a rejected payment unchanged. A re-send with the same wrong field comes back with the same code, and a duplicate re-send can create a second, live payment.
