BA Artifact Library: Templates You Can Use at Work

Three working templates from real payments change work. Download them, fill them in for your own change, and keep them in your project pack. The templates are free to use for learning and at work.

Business Requirement Document template

A full BRD template for a payments change, with a worked MT103 to pacs.008 migration example in each major section so you can see what good looks like. Covers purpose, scope in and out, stakeholders and approvers, as-is and to-be process, numbered functional requirements, message and field mapping, non-functional requirements, test scenarios, cutover and rollback, risks and open questions.

Download BRD template (.md)

ISO 20022 interface mapping

A mapping spreadsheet covering MT103 to pacs.008.001.10, MT202 to pacs.009.001.08, MT940 to camt.053.001.08, and MT101 to pain.001.001.11. Each row gives the MT field, the ISO 20022 element and XPath, data type, maximum length, whether it is mandatory or optional, mapping notes, and truncation risk. Use it as the starting point for your own interface specification.

Download interface mapping (.csv)

Test harness scenarios

A test scenario sheet for a payments test harness. It covers the happy path plus missing mandatory fields, invalid BICs, duplicate payments, closed accounts, cut-off breaches, settlement dates on TARGET2 holidays, sanctions hits, amount limit breaches, and character set violations, with the expected rejection or return code for every scenario.

Download test harness scenarios (.csv)

How to use these templates

  1. Start with the BRD. Fill in the scope and the worked example, then replace the example with your own change.
  2. Use the interface mapping to agree every field with the counterparty bank or the vendor before build starts. A field agreed late is a defect found late.
  3. Run the test harness scenarios in order. A scenario that has no expected rejection code is not a test, it is a guess.
  4. Keep all three in version control with the project. When a field mapping changes, update the BRD and the test scenarios in the same change.
