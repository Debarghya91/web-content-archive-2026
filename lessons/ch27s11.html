Key terms

Authorisation: Approval by the issuer for a card transaction to proceed, confirming the card is valid and funds or credit are available.

Mandate: An authorisation given by a debtor to a creditor to collect payments from the debtor account by direct debit.

A2A: Application to application, a mode of connecting systems directly so they exchange messages without human input.

Transcript and full text

Show transcript

An AI agent is software that perceives, decides, and acts on behalf of a user, carrying out multi-step tasks without a human driving each step. When the task includes making a payment, the agent needs more than intelligence: it needs protocols for using tools, for talking to other agents, and for proving its authority. The agent stack is the set of layers that makes an agent work, and two protocols define its foundation: MCP, for tool access, and A2A, for agent to agent communication. This lesson covers the stack. The next covers the payment protocols built on it.

MCP, the Model Context Protocol, was published by Anthropic in November 2024, and it is the tool access substrate of the agent stack. A language model on its own cannot check a balance, send a payment, or query a database: it needs tools. MCP standardises how the model discovers and calls tools. An MCP server exposes tools, with names, descriptions, and structured arguments. The model asks the server what tools exist, chooses one, and calls it with structured input. The server executes the tool and returns the result. The standardisation means any MCP compatible model can use any MCP compatible tool, without custom integration for each pair.

A2A, the Agent-to-Agent protocol, was published by Google in April 2025, and it standardises how agents communicate with each other. An agent advertises itself with an agent card: what it can do, how to reach it, and what authentication it needs. Another agent discovers the card, sends it a task, and tracks the task to completion, receiving progress updates and the final result. A2A handles the delegation: one agent asking another to do part of the work, with the task state visible to both. Where MCP connects a model to tools, A2A connects an agent to other agents, and the two together let agents form teams.

The agent stack layers the pieces. At the base is the model, which reasons and decides. Above it are the tools, reached through MCP: databases, APIs, payment systems, and document stores. Alongside are the other agents, reached through A2A: specialists the agent delegates to. Memory holds the context: what the user asked, what has been done, and what was learned. Guardrails constrain the behaviour: what the agent may and may not do, what needs human approval, and what is forbidden outright. Each layer has its own protocol, its own failure modes, and its own security needs, and the stack is only as trustworthy as its weakest layer.

Payments make the stack concrete. An agent that pays needs authorisation: whose money, what limits, and what approval. It needs identity: which agent, acting for which user, under which mandate. It needs audit: what was decided, on what evidence, and by which layer. And it needs controls: spending limits, payee restrictions, and human approval above thresholds. The payment protocols in the next lesson, AP2, TAP, Agent Pay, ACP, UCP, and x402, build on the MCP and A2A foundation, adding the payment specific identity, mandate, and attestation that the base protocols do not provide.

The risks of the stack are the risks of delegation without sufficient control. Prompt injection: malicious instructions hidden in data the agent reads, a web page, a document, an email, that steer the agent to act against the user interest. Tool misuse: an agent calling a payment tool with wrong parameters, or calling a tool it should not have access to. Delegation confusion: a task passed between agents until nobody knows which agent authorised the payment. The defences are layered like the stack: input validation, tool access control, delegation records, spending limits, and human approval for money movement. An agent that can pay must be governed like a payment system, not like a chatbot.
