Key terms

ISO 20022: An international standard for financial messaging that defines XML message formats for payments, securities and trade.

pacs.008: An ISO 20022 message for a financial institution to financial institution customer credit transfer. It replaces MT103 in cross border payments and carries structured debtor, creditor, charges and...

Gateway: A service that connects a merchant website or app to payment networks and acquirers. It encrypts card data, routes authorisation requests, and returns the result to the merchant.

  1. What to do. List the main blocks of the message, name the field that carries the amount, and name the field that identifies the payment.

Correct result. The message is made of blocks, each carrying a part of the payment instruction. The amount field and the identification field are the two a receiving bank checks first, because without them it cannot process or reconcile the payment.

Why. A message is only useful if you can read it. The blocks tell the receiving bank what to do, and the amount and identification fields are what it checks first.

Routing begins when the sender enters the receiver BIC in the payment system. The system first checks that the BIC is well formed, with four letters for the bank code, two letters for the country code, and two characters for the location code. It then checks the SWIFT BIC directory to confirm that the BIC exists, is live, and is connected to SWIFTNet. If the BIC is mistyped, for example BSCHESMN instead of BSCHESMM, the directory lookup will fail and the payment will be stopped before it leaves the bank. That early check prevents a message being sent to a bank that does not exist. Once the BIC is validated, the sending bank creates the MT message, signs it, and hands it to Alliance Gateway, which encrypts it and sends it to SWIFTNet. SWIFTNet reads the receiver BIC in the message header and looks up the destination in its routing tables. It then forwards the message to the SWIFT operating centre that serves that receiver, and from there to the receiver own gateway. The whole journey usually takes a few seconds, even for a message from Paris to Singapore, because SWIFTNet is a dedicated network with no public internet hops in the path. SWIFTNet uses a store and forward model for FIN messages. If the receiver is online, the message is delivered immediately and an acknowledgement is returned to the sender. If the receiver is offline, for example during a system upgrade at 2 in the morning in Singapore, SWIFTNet stores the message securely and delivers it when the receiver reconnects. The sender receives a delivery acknowledgement that proves the message was delivered, and the receiver receives a message that it can process and archive. That acknowledgement is the evidence operations teams use when a customer asks whether a payment was sent. If the receiver BIC is correct but the message cannot be delivered, SWIFTNet returns a negative acknowledgement, known as a NAK, with a reason code. A NAK might mean that the receiver gateway is rejecting messages, that the message format is invalid, or that the receiver has closed its session. The sender must then investigate, correct the problem, and resend the message. A payment of 150,000 euros from Milan to Toronto that received a NAK because the Toronto bank was running a weekend upgrade was resent on Monday morning and delivered in seconds, with no loss of the original instruction. Routing also depends on the category and the service. A FIN message, such as an MT103, is routed through the FIN service, which is designed for store and forward messaging. An InterAct message is routed through a different service that supports interactive request and response, while a FileAct message is routed through a file transfer service. The BIC is the same in each case, but SWIFTNet uses the service name in the header to choose the right path. A bank that sends a pacs.008 ISO 20022 message through InterAct to DBS Bank in Singapore uses the same BIC DBSSSGSG as it would for an MT103, but the service and the routing are different.
