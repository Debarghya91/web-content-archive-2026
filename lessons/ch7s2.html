Key terms

Reconciliation: The process of comparing records from two sources, such as a bank statement and an internal ledger, to confirm they agree.

Settlement: The final movement of funds between banks to discharge obligations created by cleared payments. Settlement is usually made in central bank money or through correspondent accounts.

ISO 20022: An international standard for financial messaging that defines XML message formats for payments, securities and trade.

  1. What to do. List the three levels of the message and name the field that carries the amount and the field that carries the end-to-end reference.

Correct result. The amount is carried in the instructed amount element and the reference in the end-to-end identification. The three levels are the group header, the payment information, and the credit transfer transaction information.

Why. A message is only useful if you can read it. The group header identifies the message, the payment information identifies the batch, and the transaction information carries the single payment.

Transcript and full text

Show transcript

The Group Header is the first block in a pacs.008, and it contains information about the message as a whole rather than about any single transaction. It includes the Message Identification, which is a unique reference assigned by the sender to identify the message, the Creation Date and Time, which records when the message was created, and the Number of Transactions, which states how many credit transfer transactions are contained in the message. It also includes the Control Sum, which is the total of all the transaction amounts, and which can be used to check that no transaction has been lost or corrupted in transit.

The Group Header also contains the Initiating Party, which identifies the party that created the message, and in some usage guidelines it contains the Settlement Information, which describes how the message will be settled, for example whether settlement is through a specific clearing system or through a correspondent account. The Group Header is not just administrative, it is used for validation, for tracking, and for reconciliation. If the Number of Transactions does not match the actual number of transactions in the message, the message will be rejected.

If the Control Sum does not match the sum of the transaction amounts, the message will also be rejected, because that mismatch suggests a data error. For a business analyst, the Group Header is important because it is the first place to look when a message fails validation. A duplicate Message Identification can cause a message to be rejected as a duplicate, even if the transactions are new. A Control Sum error can cause an entire file to be held, even if only one transaction is wrong. Your requirements should state how the Message Identification is generated, how uniqueness is ensured, and how the Control Sum is calculated.

You should also ensure that operations teams know how to read the Group Header, because it is the envelope that tells them how many payments to expect and what the total value should be.
