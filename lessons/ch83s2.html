Key terms

Certification: The scheme's proof that a product works, earned by passing the scheme's test pack. The firm runs the test pack against the scheme's test environment and submits the results as evidence.

Settlement: The final movement of funds between banks to discharge obligations created by cleared payments. Settlement is usually made in central bank money or through correspondent accounts.

pacs.008: The ISO 20022 FI to FI customer credit transfer message, used for cross-border payments under CBPR+. It is the ISO 20022 successor to MT103 and carries the debtor, creditor, charges and remittance information in structured elements.

Practise this lesson

Exercise

Review the three SEPA test pack results and decide which are certification failures, and state the correct creditor name limit.

  1. What to do. Compare each result against the test pack: the expected reason code, the 25 minute pacs.002 deadline, and the 70 character SEPA name limit.

Correct result. All three are certification failures. The AC04 code is wrong, because the test expected AM04. The pacs.002 was late, because the test pack requires it within 25 minutes and it was sent after 40 minutes. The 90 character name was rejected because the SEPA scheme rule limits the name to 70 characters, even though ISO 20022 allows 140 characters in the pacs.008 name element, so the name is valid ISO 20022 but fails the SEPA test pack.

Why. The test pack defines the expected reason code, the response deadline and the field format. A wrong reason code, a missed deadline and a field over the scheme limit are each a defect the scheme would record. The name is the classic trap: 140 characters is the ISO 20022 Max140Text limit, and the SEPA rule is 70 characters.

Certification is the scheme's proof that the product works, and it is earned by passing a test pack, not by asserting it. A test pack is a set of test cases published by the scheme, each with an input, an expected output, and a pass criterion. For SEPA the test pack includes sending a pacs.008 and receiving a pacs.002, handling a reject with the correct reason code, processing a return with a pacs.004, and responding to a recall with a camt.029. For a card scheme the test pack includes authorisation, clearing, settlement, chargebacks and reversals. The firm must pass every mandatory test case. The certification window is a scheduled period during which a card scheme runs the tests. The firm books a window, runs the test pack against the scheme's test environment, and submits the results. For SEPA there is no certification window booked with the European Payments Council. The firm proves it can send and receive the scheme messages by testing with its clearing mechanism, and it keeps that evidence under its adherence agreement. If a test fails, the firm fixes the defect and books another window. The windows are limited, and the scheme may have a queue, so a failed attempt can delay go-live by weeks. The project plan must therefore allow for at least one failed attempt, and the team must not treat the first window as a formality. Test data is a discipline of its own. The scheme's test environment needs test IBANs, test BICs, test card numbers, and test customer names that will trigger specific behaviours. A test IBAN that triggers a reject, a test card that triggers a decline, and a test name that triggers a sanctions hit must all be available, and the team must know which test data triggers which behaviour. The requirements must state the test data set, and the test data must be kept separate from production data, because a test payment that reaches production is a real payment. Common certification failures are predictable, and a good team prepares for them. The most common is the reason code: the firm returns a payment with AC04 when the scheme expects AM04, or rejects with FF01 when the scheme expects AG01. The second is the timing: the firm sends the pacs.002 status report after the scheme's deadline, or the pacs.004 return after the cut-off. The third is the field format: a name longer than 140 characters, a remittance reference longer than 140 characters, or an address that is not structured. The 140 character limit is the ISO 20022 Max140Text limit for the name element in pacs.008. The SEPA scheme rule limits the name to 70 characters, so a name between 70 and 140 characters is valid ISO 20022 but fails the SEPA test pack. Each of these is a defect that should have been caught in internal testing. Regression testing after certification is a continuing obligation. When the scheme publishes a new rulebook, the firm must re-run the test pack against the new rules, and must prove the changes work before the new rulebook takes effect. The EPC publishes a new SEPA rulebook every year, effective in November, and the firm must implement the changes and test them with its clearing mechanism before the effective date. Participation continues under the adherence agreement, and the EPC does not re-certify participants each year, so there is no annual re-certification to plan for. The requirements must therefore include the annual rulebook change, and the project plan must reserve time for it every year. Certification evidence must be retained. The scheme may ask for the test results, the defect log, and the sign-off, months after the certification. The evidence must be stored in a place the team can find, with the test pack version, the date, and the name of the person who ran the tests. A firm that cannot produce its certification evidence will be asked to re-certify, which costs time and money. The acceptance criteria must include a test where the evidence is retrieved and shown to be complete. For a business analyst, the test pack is a requirements document. Each test case maps to a requirement, each requirement maps to a test case, and the traceability matrix proves the coverage. The acceptance criteria must include a test where the traceability matrix is checked and every requirement has at least one test case.
