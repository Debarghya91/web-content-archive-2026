Key terms

Authorisation: Approval by the issuer for a card transaction to proceed, confirming the card is valid and funds or credit are available.

Mandate: An authorisation given by a debtor to a creditor to collect payments from the debtor account by direct debit.

A2A: Application to application, a mode of connecting systems directly so they exchange messages without human input.

  1. What to do. State what happens at each stage, who pays whom, and when the merchant is actually credited.

Correct result. Authorisation holds the funds and returns a response code. Clearing sends the transaction in a batch file. Settlement moves the net amount between banks, and the acquirer credits the merchant after deducting interchange, scheme fees and its margin.

Why. A card payment is not one event. The customer sees it on Monday, the merchant gets it on Wednesday, and the difference is the clearing and settlement cycle.

Six protocols, from six different parts of the industry, aim at the same problem: how does an AI agent pay safely? AP2, from Google and partners. TAP, from Visa. Agent Pay, from Mastercard. ACP, from OpenAI and Stripe. UCP, from Google and Shopify. And x402, from Coinbase. Each brings the trust model of its origin: the web platform, the card network, the commerce platform, or the crypto exchange. The protocols overlap, compete, and in some cases build on each other, and the landscape is moving fast. This lesson maps the six, so that the next development in the field lands on a prepared mind.

AP2, the Agent Payments Protocol, was published by Google in September 2025 with more than sixty partners, and it is defined as an extension of A2A and MCP. Its core idea is signed mandates as verifiable credentials. The Intent Mandate records what the user wants. The Cart Mandate records what is being bought, at what price. The Payment Mandate authorises the payment, signed by the user. Each mandate is a signed, verifiable credential that travels with the transaction, so that every party can verify what was authorised, by whom, and for what. Version 0.2 was contributed to the FIDO Alliance in April 2026, moving the protocol toward open governance. AP2 is the mandate model: authority expressed as signed credentials.

The card networks bring network trust. Visa Trusted Agent Protocol, TAP, published in October 2025, provides agent identity, signed HTTP attestation, payment claims, and the Visa Agentic Registry: a registry of verified agents that merchants and issuers can trust. Mastercard Agent Pay, published in April 2025, provides Agentic Tokens, payment credentials bound to registered agents, so that a payment credential can only be used by the agent it was issued to. Both protocols let agents pay over the existing card rails, with the network standing behind the agent identity and the transaction. The card model is: the network knows the agent, the network vouches for it, and the existing rails carry the money.

The commerce protocols cover the shopping journey, not just the payment. ACP, the Agentic Commerce Protocol, from OpenAI and Stripe, published in September 2025, defines the checkout exchange: the agent and the merchant negotiate the purchase, and payment is made with a Shared Payment Token, so the agent never holds the raw card details. UCP, the Universal Commerce Protocol, from Google and Shopify, published in January 2026, covers discovery to checkout in one protocol: the agent finds the product, agrees the terms, and pays, while the merchant stays the merchant of record. Both aim at the full journey, because an agent that can pay but cannot shop, or can shop but cannot pay securely, solves only half the problem.

x402 takes a different route: the web itself. Published by Coinbase in May 2025, x402 revives HTTP status code 402, Payment Required, for stablecoin payments. A server responds to a request with a 402 and a price. The agent pays in USDC, the dollar stablecoin, on the Base blockchain, using EIP-3009 gasless authorisation, so the agent does not need the native token for gas. The server verifies the payment and delivers the response. x402 suits micropayments and pay per use APIs: an agent paying a fraction of a dollar for a single API call, a single document, or a single computation, without accounts, subscriptions, or cards.

The six protocols converge on shared patterns, even as they compete. Identity: the agent must be identifiable and verifiable. Signed mandates or attestations: the authorisation must be provable, not just asserted. Registries: trusted lists of agents, merchants, and credentials. And tokenised credentials: the agent holds a token, not the raw payment credential. For a business analyst, the evaluation questions are the same for all six: what is the trust model, which rails carry the money, who governs the protocol, and what happens when something goes wrong? The field will change, protocols will merge or fade, but the questions, and the patterns, will survive.
