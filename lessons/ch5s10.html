Key terms

Cover payment: A payment method where the customer instruction travels one route while the funds travel separately as a bank to bank cover message.

Value date: The date on which funds become available to the beneficiary and on which interest starts to accrue. It is the date used for settlement and for nostro posting.

SWIFT: The Society for Worldwide Interbank Financial Telecommunication, a member owned cooperative that provides secure messaging services for financial institutions.

Correct result. The message is made of blocks, each carrying a part of the payment instruction. The amount field and the identification field are the two a receiving bank checks first, because without them it cannot process or reconcile the payment.

Why. A message is only useful if you can read it. The blocks tell the receiving bank what to do, and the amount and identification fields are what it checks first.

Every SWIFT MT message is built from up to five blocks, each wrapped in curly brackets and numbered 1 to 5. Block 1 is the basic header. It is the only mandatory block. It contains general information that identifies the message and some control information. It has five fields, all mandatory, the application identifier (F for FIN), the service identifier (01 for FIN), the logical terminal address of the sender (a 12 character BIC plus branch code), the four digit session number, and the six digit sequence number. A full example is {1:F01SOGEFRPPAXXX0070970817}, where SOGEFRPPAXXX is Societe Generale Paris, 0070 is the session number, and 970817 is the sequence number. Block 2 is the application header. It contains information specific to the application. It is required for messages that users or systems exchange. There are two variations. An input header starts with the letter I and describes a message a bank is sending into the network. It carries the message type, the receiver BIC, and the priority, for example {2:I103BSCHESMMXXXXN}, an outgoing MT103 to Santander at normal priority. An output header starts with the letter O and describes a message SWIFT has delivered. It is longer because it adds the history inside the network, message type, input time, input reference date, sender logical terminal, session and sequence numbers, output date, output time, and priority. An example is {2:O1031734150713DEUTDEFFBXXX00739698421607131634N}, an MT103 that arrived from Deutsche Bank. Block 3 is the user header. It is optional on most messages. It carries tagged items such as tag 103 for a FINCopy service, tag 108 for a message user reference of up to 16 characters, tag 111 for a service type identifier, tag 119 for the validation flag that marks an MT202 as a cover payment, and tag 121 for the Unique End-to-end Transaction Reference used in SWIFT gpi tracking. Block 3 becomes mandatory in one case. When a message goes through FINCopy, tag 103 must be present so SWIFT knows which copy service should receive the message. Block 4 is the text block. It holds the business data of the payment, organised as tagged fields. Each field starts with a colon, a two digit field number, an optional letter for the field option, and another colon, for example :20: for the transaction reference, :32A: for the value date and settled amount, and :59: for the beneficiary customer. Amounts use a comma as the decimal separator, so USD 367,574.90 is written as USD367574,90. Dates use the format YYMMDD, so 18 July 2024 is written as 180724. Multi line fields such as 50, 59, and 70 use line breaks, with each line limited to 35 characters. Block 5 is the trailers block. It indicates special circumstances related to message handling or contains security information. The checksum is the best known trailer. A complete raw message looks like this. {1:F01SOGEFRPPAXXX0070970817}{2:O1031734150713DEUTDEFFBXXX00739698421607131634N}{3:{103:TGT}{108:OPTUSERREF16CHAR}}{4: :20:UNIQUEREFOFTRX16, :23B:CRED, :32A:180724EUR735927,75, :33B:EUR735927,75, :50A:/DE37500700100950596700, DEUTDEFF, :59:/FR7630003034950005005419318, CHARLES DUPONT COMPANY RUE GENERAL DE GAULLE, 21 75013 PARIS :71A:SHA -}{5:{CHK:D628FE0165A7}}. Read it block by block, who sent it, what type it is, any user header data, the business fields, and the checksum. That skill lets an analyst read any MT message without a tool.
