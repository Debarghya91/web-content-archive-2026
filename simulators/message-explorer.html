ISO 20022 Message Explorer

ISO 20022 Message Explorer

Structured XML examples for the eleven messages that carry a payment from instruction to statement and back again. One payment tells one story here: INV-8841 (Acme Manufacturing Ltd to Tanaka Trading Pte Ltd, Singapore, USD 25,000, charge bearer SHAR, charges USD 20 + USD 22 = USD 42, beneficiary receives USD 24,958) runs pain.001, pacs.008, pacs.009, pacs.002 (ACSC), pain.002, camt.052, camt.053 and camt.054. The return (pacs.004, INV-9021) and the recall and its refusal (camt.056 and camt.029, INV-9100) are separate payments, clearly labelled as such. Each example states its message version and namespace. Every example is checked for well-formedness and for the structural rules in _validate_xml_examples (SttlmInf in GrpHdr only, camt.056 Agt and TxInf/Case wrappers, camt.053 FrToDt and nested dates, UETR and ChrgBr in pacs.008); full XSD validation against the published schema for each stated version is a build-time step outside this module. Pick a message, expand and collapse the nodes by clicking the plus and minus buttons, and click any field name to see its business meaning, cardinality, whether it is schema optional or business mandatory, an example value, its mapping from the MT equivalent where one exists, and the common validation errors for that field.

pacs.008.001.08: FI to FI Customer Credit Transfer

The interbank customer credit transfer. It replaces MT103 for in-scope cross-border customer payments under CBPR+ and carries the full structured debtor, creditor, charges, and remittance data. pacs.009.001.08: FI to FI Credit Transfer (cover, COV)

The bank to bank credit transfer (cover, COV variant). It replaces MT202COV and moves bank funds: the settling cover leg for the INV-8841 customer payment, SttlmMtd INDA. It is distinct from pacs.009 ADV (SttlmMtd COVE), which is advice only: an ADV carries information, does not move funds, and must be accompanied by a CORE or COV that settles. COVE is not a valid purpose code, so this example uses TREA.

pacs.002.001.10: FI to FI Payment Status Report

The interbank status report. Under CBPR+ only the negative notification (RJCT) is mandatory for all agents; positive and pending statuses are governed by bilateral agreement, so this ACSC (settlement completed) report is shown as a bilateral-agreement positive status. SEPA SCT uses pacs.002 for rejects only (no news means accepted); only SCT Inst uses it as a genuine confirmation in both directions. This report confirms INV-8841 reached ACSC on 2026-11-06. The full status ladder is ACTC, ACCP, ACSP, ACSC, ACCC.

pacs.004.001.09: Payment Return

The payment return. It sends funds back to the debtor agent when the creditor agent cannot credit the beneficiary, for example a closed account. A return happens AFTER settlement, and only the creditor agent sends it. This is a SEPARATE payment from INV-8841: reference INV-9021, original USD 85,000, returned USD 84,980 after a USD 20 intermediary fee (charge bearer SHAR), reason AC04. A returned amount can never exceed the original payment.

camt.056.001.08: FI to FI Payment Cancellation Request

The payment cancellation request. It asks the next bank to return funds already sent, for example after a duplicate payment or a customer error. It starts a recall. This is a SEPARATE payment from INV-8841: reference INV-9100, USD 12,500, reason DUPL. The ISO cancellation-reason list is wider than the EPC SCT recall list: EPC bank-initiated recall uses DUPL, TECH and FRAD only (10 banking business days, 13 months for fraud; the beneficiary bank answers within 15 banking business days, positively by pacs.004 with reason FOCR, negatively by camt.029). The customer-requested route (CUST) is a separate procedure.

pacs.008 version comparison: CBPR+ rules versus SEPA rules

AreaCBPR+ rules (cross-border)SEPA rules (euro area)
ScopeCross-border payments between banks worldwide, replacing MT103 for in-scope payments.Euro credit transfers inside the SEPA area, under the SEPA rulebook.
Debtor and creditor addressStructured or hybrid address with at least town name and country. The November 2026 structured-address mandate was signalled as deferred by SWIFT on 27 August 2026, with no replacement date published at the time of writing: do not treat it as settled, check the current SWIFT SR2026/SR2027 notes.Unstructured addresses are no longer permitted from 15 November 2026 (inter-PSP settlement date). Structured address is required.
BICDebtor agent and creditor agent BICs are required for routing through correspondents.BIC is not required. The IBAN alone identifies the account and the bank.
PurposePurpose code is recommended and supports screening and reporting.Purpose code is optional and rarely used by most schemes.
Charges (ChrgBr)DEBT, CRED or SHAR. This payment uses SHAR, so intermediaries may deduct from the principal.SLEV only. The full amount must reach the creditor.
UETRBusiness mandatory: a UUID v4 carried through every bank in the chain.Optional.
Transactions per message (NbOfTxs)Exactly one transaction per pacs.008 (NbOfTxs = 1).Multi-transaction pacs.008 is permitted under SEPA batch usage.
pacs.002 usageOnly the negative notification (RJCT) is mandatory for all agents; positive and pending statuses are by bilateral agreement.SCT uses pacs.002 for rejects only (no news means accepted). SCT Inst uses it as a genuine confirmation in both directions.
SettlementSettlement uses correspondent accounts, nostro funding, and the COVE cover method where needed.Settlement is through the SEPA clearing system and central bank accounts. No cover payment is used.
Remittance informationStructured and unstructured remittance information are both supported. Ustrd is limited to 140 characters.Structured remittance information is preferred so the creditor can reconcile automatically. Ustrd is limited to 140 characters.
Character setThe full Latin character set is supported, with restrictions on some symbols.Only the Latin character set defined by the SEPA rulebook is allowed.
Value date and timingValue dates follow correspondent and clearing cut off times across time zones.Execution follows the SEPA maximum execution time of one business day, and instant payments settle in seconds.
Return and rejection codesReturns use pacs.004 with the full ISO reason code list, for example AC04 for a closed account. Reject (pacs.002) is before settlement; return (pacs.004) is after settlement.Returns and rejects follow the SEPA reason code list, with the same AC and MD codes for the common cases. Recall uses DUPL, TECH and FRAD only (EPC SCT bank-initiated recall).
