Unit 0: Onboarding

Start here. What an agent is, how this course works, and how to set up your tools.

3 lessons. About 3 to 4 hours.

Lesson 0.1: What an AI agent is

An AI agent is a program that takes a goal, decides what to do next, uses tools to act, looks at the result, and repeats until the goal is done or it needs help. A chatbot answers one question and stops. An agent keeps going across several steps. The difference is the loop: think, act, observe, and then think again. The agent is not magic and it is not a person. It is a language model wrapped in a control loop, with tools that let it read data and take actions. In payments, that loop fits real work. A payment status check is a good example: the agent looks up the payment, reads the status, checks what the status means, and drafts the reply. A human still approves anything that moves money or tells a customer something final. Agents are useful when a task has clear steps, clear data sources, and a clear way to check the answer. They are a poor fit when the rules are unclear, the data is unreliable, or a mistake would be costly and hard to undo. This course teaches you to build agents for the first kind of task, with checks at every step.

Worked example

A customer asks where their payment is. A plain chatbot guesses from memory. An agent instead calls a status lookup tool with the payment reference, reads the returned status, and only then answers. If the tool says the payment is held for a missing field, the agent reports exactly that and suggests the next step. It does not invent a delivery date. The agent did three things a chatbot did not: it used a tool, it read fresh data, and it based its answer on that data. That is the whole idea of this course in one small task.

Hands-on exercise

  1. Write down one payments task you do often that has clear steps and a clear answer, for example checking a payment status.
  2. List the data sources that task needs, such as a payment log or a scheme rulebook.
  3. List what could go wrong if the agent got it wrong, and who would catch the error.
  4. Decide whether a human should approve the result before it is sent, and write down why.

Lesson 0.2: How this course works

This course has five units and two bonus units. Unit 0 is onboarding. Unit 1 teaches the fundamentals: the think, act, observe loop, tools, and how a language model works as the brain of an agent. Unit 2 compares three frameworks so you can pick the right one for a job. Unit 3 applies agents to three payments use cases. Unit 4 is the final project, where you build and evaluate a payments exception triage agent. The two bonus units cover fine-tuning for function calling and observability. Each lesson follows the same shape: short theory, a worked payments example, a hands-on exercise, and a quiz of four questions. Work at the suggested pace of one unit per week, at 3 to 4 hours per week. Do the exercises, not just the reading, because building is where the learning happens. Pass the Unit 1 quiz to earn the Certificate of Fundamentals. Finish Units 1, 3 and 4 to earn the Certificate of Completion. Certificates are stored in this browser only, so use the same browser for the whole course. If you get stuck, go back one lesson and rebuild the small example there before moving on.

Worked example

A learner finishes Unit 1 on a Monday, does the exercises on Wednesday, and passes the Unit 1 quiz on Friday. The quiz script records the pass in this browser, and the course overview page then shows the Certificate of Fundamentals as earned. The learner then works through Unit 2 the next week and Unit 3 the week after. By the final project, the earlier lessons are still fresh because each unit was practised, not just read. That steady weekly rhythm is the intended path through this course.

Hands-on exercise

  1. Open the course overview page and read the units list and the completion criteria.
  2. Plan one weekly study slot of 3 to 4 hours and write it in your calendar.
  3. Pick the payments task from Lesson 0.1 that you will use as your running example through the course.
  4. Complete the Lesson 0.1 exercise before starting Unit 1.

Lesson 0.3: Tools setup

You need three things before Unit 1: Python, a code editor, and a model to run. Install a recent Python version and check it by running python --version in a terminal. Use any editor you already know. For the model, use a local model with Ollama on your own computer. Ollama is free and open-source, needs no account and no payment, and you run the model yourself: install Ollama, then pull a small model with ollama pull qwen2.5:7b. A note on hosted inference: hosted model services are now pay-as-you-go, with no free monthly inference credits on free accounts, so they need purchased credits. Do not plan on free hosted inference. The free route in this course is the local Ollama model, and the code is written with a swappable model, so you can point it at any provider you choose. If you use a hosted provider instead, keep its API key private: never paste it into a shared document, a chat, or a public code repository. Install the three libraries used in this course. All three are free, open-source, and pip-installable: smolagents 1.26.0, langgraph 1.2.24, and llama-index 0.14.26. Install them with pip install smolagents langgraph llama-index, then check each install by importing it in Python. The examples in this course use small, well known patterns only, and they are written to be read and adapted, not copied blindly. If an install fails, read the error message first: it usually names the missing piece. Work in a fresh folder for this course so your files stay together. Keep one notes file where you record what worked, what failed, and the exact error text, because that record is what lets you fix the next problem faster. Do not move on until Python runs and the library imports.

Worked example

A learner installs Python, runs python --version, and sees a version number. They create a project folder called ai-agents-payments, install the library, and run a one line import test in Python. The import works, so they write the version and the date in their notes file. When a later example fails, they can check this note and confirm the setup itself was fine, which narrows the problem to the new code. Ten minutes of setup notes saves an hour of guessing later.

Hands-on exercise

  1. Install a recent Python version and confirm it with python --version.
  2. Create a project folder for this course and a notes file inside it.
  3. Install Ollama, pull a small local model, and confirm it answers one test prompt. If you use a hosted provider instead, save the API key securely and never share it.
  4. Install smolagents, langgraph, and llama-index with pip and confirm each import works in Python.
  5. Write the Python version, the date, and any errors you hit in your notes file.
