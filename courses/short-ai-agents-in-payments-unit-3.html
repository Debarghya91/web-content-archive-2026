Unit 3: Use Cases

Agentic RAG over scheme rules, a reconciliation agent, and an exception triage agent.

3 lessons. About 3 to 4 hours.

Lesson 3.1: Agentic RAG over scheme rules

Agentic RAG means the agent decides when to search your documents and what to search for, instead of following a fixed search step. The flow is: the agent reads the task, thinks about what fact it needs, calls a search tool, reads the retrieved passages, and only then answers. The retrieved passages are the evidence. The agent must quote them or name them, and must say when the retrieved text does not answer the question. In payments, the documents are scheme rule extracts and internal procedure notes. The index holds short, focused passages with clear headings, so the search returns the right passage instead of a long mixed page. The agent never answers a rule question from memory when the index is available. If the search returns nothing useful, the agent says so and asks a human, rather than guessing. The rule for every answer is the same: no retrieved passage, no rule claim. When a rule is uncertain or may have changed, write "check the current scheme rulebook" instead of stating a specific rule.

Run it

from smolagents import CodeAgent, LiteLLMModel, tool

RULES = {
    "missing field": "A payment held for a missing field waits for the sender to supply the field. Do not release it early.",
    "duplicate payment": "A suspected duplicate payment must be checked against the original reference before any refund.",
}

@tool
def search_scheme_rules(query: str) -> str:
    """Search the scheme rule extracts for a short query.
    Args:
        query: a short search phrase, for example missing field.
    """
    return RULES.get(query, "No matching rule passage found.")

model = LiteLLMModel(
    model_id="ollama_chat/qwen2.5:7b",
    api_base="http://127.0.0.1:11434",
    num_ctx=8192,
)
agent = CodeAgent(tools=[search_scheme_rules], model=model, max_steps=5)
answer = agent.run(
    "What should we do when a payment is held for a missing field?"
)
print(answer)

Install first with pip install "smolagents[litellm]" and start Ollama with ollama pull qwen2.5:7b. The model is swappable: change the model_id and api_base to point at any provider you choose. If an import name differs in your installed version, check that version's docs; the pattern stays the same.

What you should see:

A payment held for a missing field waits for the sender to supply the field. Do not release it early. Check the current scheme rulebook for the latest wording.

Your wording may differ slightly. The answer must repeat the retrieved rule and must not add a rule the search did not return.

Lesson 3.2: A reconciliation agent

Reconciliation is matching two lists and finding the breaks: entries on one side with no match on the other, or entries that match on reference but differ on amount or status. An agent does this well because the job is a loop over clear checks with a clear output: a list of breaks, each with the evidence. The agent needs two tools, one for each side, for example a ledger lookup and a bank statement lookup. It fetches both lists for the same day, matches them by reference, and reports each break with the two sides shown. It must never silently drop an entry it cannot match. An unmatched entry is a break, not a detail to skip. The agent also needs a rule for what it may fix itself and what it must escalate. A safe rule: the agent reports breaks and suggests causes, and a human decides any correction or customer message. The value is speed and completeness: the agent checks every entry, including the ones a tired reviewer might skip, and the break list is the audit trail.

Run it

from smolagents import CodeAgent, LiteLLMModel, tool

LEDGER = {"PAY-1042": "held", "PAY-1043": "complete", "PAY-1045": "complete"}
STATEMENT = {"PAY-1042": "held", "PAY-1043": "complete"}

@tool
def get_ledger(day: str) -> str:
    """Get the ledger entries for one day.
    Args:
        day: the day to check, for example 2026-11-27.
    """
    return str(LEDGER)

@tool
def get_statement(day: str) -> str:
    """Get the bank statement entries for one day.
    Args:
        day: the day to check, for example 2026-11-27.
    """
    return str(STATEMENT)

model = LiteLLMModel(
    model_id="ollama_chat/qwen2.5:7b",
    api_base="http://127.0.0.1:11434",
    num_ctx=8192,
)
agent = CodeAgent(tools=[get_ledger, get_statement], model=model, max_steps=6)
answer = agent.run(
    "Reconcile 2026-11-27. List every break with the evidence."
)
print(answer)

Install first with pip install "smolagents[litellm]" and start Ollama with ollama pull qwen2.5:7b. The model is swappable: change the model_id and api_base to point at any provider you choose.

What you should see:

One break: ledger shows PAY-1045 as complete, but the statement has no PAY-1045. All other entries match.

Your wording may differ slightly. The answer must name the break with both sides shown, and must not claim all entries match.

Lesson 3.3: An exception triage agent

Exception triage is the first decision on a failed or held payment: what happened, how urgent is it, who should handle it, and what happens next. An agent triages by following a fixed order: check the status, find the reason, check the rule, then decide the route. The route is one of three: resolve with a standard reply, escalate to a specialist, or ask the sender for missing information. The agent must show its evidence at each step, so a human can check the triage without re-doing it. It must never invent a reason, a rule, or a timeline. It must also know its limits: an exception it has never seen, or a reason the tools cannot explain, goes to a human with the evidence gathered so far. A good triage agent is boring in the best way: same order, same evidence, same three routes, every time. The speed comes from doing the lookups at once and writing the summary in a fixed format, not from skipping steps.

Run it

from smolagents import CodeAgent, LiteLLMModel, tool

STATUS = {"PAY-1042": "held, reason: missing field"}
RULES = {
    "missing field": "A payment held for a missing field waits for the sender to supply the field.",
}

@tool
def get_payment_status(reference: str) -> str:
    """Look up the status of a payment by its reference.
    Args:
        reference: the payment reference, for example PAY-1042.
    """
    return STATUS.get(reference, "reference not found")

@tool
def search_scheme_rules(query: str) -> str:
    """Search the scheme rule extracts for a short query.
    Args:
        query: a short search phrase, for example missing field.
    """
    return RULES.get(query, "No matching rule passage found.")

model = LiteLLMModel(
    model_id="ollama_chat/qwen2.5:7b",
    api_base="http://127.0.0.1:11434",
    num_ctx=8192,
)
agent = CodeAgent(
    tools=[get_payment_status, search_scheme_rules], model=model, max_steps=6
)
answer = agent.run(
    "Triage exception PAY-1042. Say what happened, what rule applies, "
    "and what to do next."
)
print(answer)

Install first with pip install "smolagents[litellm]" and start Ollama with ollama pull qwen2.5:7b. The model is swappable: change the model_id and api_base to point at any provider you choose.

What happened: payment PAY-1042 is held because a field is missing. Rule: a payment held for a missing field waits for the sender to supply the field. Next step: ask the sender for the missing field. Check the current scheme rulebook for the latest wording.
